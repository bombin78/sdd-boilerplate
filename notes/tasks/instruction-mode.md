# Этап по инструкции

Как пользователь делает этап сам, по инструкции, которую пишет Claude.
Claude читает этот файл, когда этап — инструкция по шагам: в начале
файла этапа написано «Этап — инструкция по шагам, выполняет
пользователь», в колонке «Вид» списка задач — «инструкция по шагам».
Всё остальное о задачах — в [README.md](README.md) рядом: оно
действует и для такого этапа.

Claude пишет инструкцию шагами `## Шаг N.`, а пользователь выполняет
её сам. Шаг бывает двух видов:

- шаг с кодом — файл, место в файле и часть кода. Пользователь читает
  код, задаёт вопросы, переносит код в файл и меняет то, что считает
  нужным сделать по-другому. Так весь код этапа проходит через
  пользователя;
- шаг с командами — где выполняется: **[компьютер]**, **[сервер]**
  или **[браузер]**, точные команды с разбором флагов, ожидаемый вывод
  и что делать, если вывод другой.

Статусы — те же, что у этапа Claude. Образец — болванка
`infra/0001-task.md`.

## Порядок работы

1. Claude читает `notes/project.md` и сверяет его с новыми коммитами,
   как в пункте 1 раздела «Как Claude делает этап с приёмкой»
   в `README.md`. Потом читает код, который меняется, и пишет в файл
   этапа раздел «План»: список шагов, по строке на шаг, без кода
   и команд. Вместе с планом Claude спрашивает, нужны ли в шагах
   с кодом пояснения: что делает часть кода и почему она написана так.
   Это зависит от того, насколько пользователь знает технологию.
   Claude предлагает ответ по разделу «Читатель»
   `notes/claude/answer-rules.md`, а решает пользователь. Ответ
   записывается в раздел «Решения пользователя» файла этапа.
   Пользователь согласился с планом — статусы этапа и задачи меняются,
   как в пункте 1 раздела «Как Claude делает этап с приёмкой».
2. Claude пишет в файл этапа полный текст следующего шага. Шаг пишется,
   только когда готов предыдущий: правки пользователя меняют код,
   на который опираются следующие шаги.
3. Пользователь выполняет шаг. Claude в это время файлы кода не меняет
   и отвечает на вопросы, например через `/explain`.
4. Пользователь говорит, что шаг готов. Если шаг с кодом, Claude
   сверяет файлы с кодом шага по `git diff`. Если пользователь поменял
   код, Claude пишет в отметку «**Сделано ГГГГ-ММ-ДД.**» в конце шага,
   что поменялось, и учитывает это в плане и в следующих шагах. Дальше —
   следующий шаг, с пункта 2.
5. После последнего шага Claude проверяет результат:
   - запускает команды списка «Перед отчётом» раздела «Проверка»
     `notes/claude/stack-rules.md`;
   - сверяет результат с каждым пунктом «Готово, когда», с правилами
     `notes/claude/code-rules.md` и `notes/claude/stack-rules.md`;
   - пишет отчёт: по каждому пункту «Готово, когда» — выполнен или нет
     и как проверен, дальше — замечания: файл, строка, что не так
     и как исправить. В конце — правки `notes/project.md`, как
     в пункте 3 раздела «Как Claude делает этап с приёмкой».

   Код Claude сам не исправляет. Перед отчётом — статус этапа «ждёт
   приёмки».
6. Пользователь исправляет замечания и снова просит проверку, как
   в пункте 5. Замечание, которое пользователь решил не исправлять
   в этом этапе, Claude записывает в `notes/backlog.md`. Приёмка,
   статусы после неё и ревью pull request — как в пункте 4 раздела
   «Как Claude делает этап с приёмкой».

## Правила текста инструкции

- шаги выполняются по порядку, без пропусков. Менять код шага можно:
  изменение записывается в отметку «Сделано», пункт 4;
- в начале файла — что проверено при подготовке, что нет, и раздел
  «Термины». Claude дополняет его, когда пишет новый шаг;
- файл показывается и разбирается в том шаге, где он создаётся; ссылки
  только назад, на прошлые шаги, без «см. ниже»;
- одно слово на одно понятие во всём файле;
- в конце — «После задачи», «Чего нельзя делать», «Источники»;
- длинные пояснения, которые раздувают инструкцию, — в отдельный файл
  рядом: `NNNN-stage-*.md`, со ссылкой из нужного шага.

Ветка и pull request — как у этапа Claude.
