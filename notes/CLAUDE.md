# Правила работы с папкой `notes`

Как Claude ведёт заметки в `notes/`. Claude Code загружает этот файл,
когда Claude читает или правит любой файл в `notes/`. Что лежит
в репозитории `notes/` и как он подключён к проекту — в `README.md`
рядом. Записи в git и поиск по заметкам — в `claude/common-rules.md`.

## Что куда класть

| Что | Куда |
|---|---|
| задачи, этапы, инструкции по шагам | `tasks/`, устройство — в `tasks/README.md` |
| разборы тем | `docs/` |
| сохранённые ответы | `docs/answers/` |
| идеи | `ideas/` |
| справочники: сервер, Docker, рекомендации | корень `notes/` |
| настройка Claude: правила, скилл, агент | `claude/` |
| хуки Claude Code | `hooks/` |
| замеченное по ходу работы и не исправленное сразу | `backlog.md` |

Новая папка или новый вид файлов — сначала предложить пользователю,
потом создавать. После создания — обновить дерево в `README.md`.

## Удаление

Claude не удаляет файлы заметок: это запрещает хук
`hooks/protect-notes.sh`. Если файл больше не нужен, Claude говорит,
какой и почему, а удаляет пользователь. Перенос и переименование (`mv`)
разрешены.

## Тексты

- Тексты для пользователя пишутся по `claude/answer-rules.md`.
- В начале файла — дата: `Дата: ГГГГ-ММ-ДД`.
- Утверждение, которое не проверено запуском или документацией,
  помечается как непроверенное.
- Подпись в начале абзаца пишется полностью и понятна без соседних
  абзацев: «**Что сделать.**», а не «**Что.**».

## Инструкции по шагам

Когда пользователь просит расписать этап или маленькую задачу как
инструкцию для себя, Claude пишет её по разделу «Как пользователь
делает этап по инструкции» в `tasks/README.md`. Образец — болванка
`tasks/infra/0001-task.md`.

## Статусы задач

- Статус этапа — только в начале файла этапа, статус задачи — только
  в `tasks/registry/<направление>.md`. Когда и какой статус ставить —
  в `tasks/README.md`, разделы «Как Claude делает этап с приёмкой»
  и «Как пользователь делает этап по инструкции».
- Что пользователь попросил поправить при приёмке — записать в файл
  этапа, раздел «Доработки по приёмке».
- Требования, которые выяснились при приёмке и действуют дальше, —
  перенести туда, где им место: в описание задачи, в
  `claude/code-rules.md` (общие правила) или в `claude/stack-rules.md`
  (правила стека).

## Ссылки

- Ссылки внутри `notes/` и на файлы проекта — относительные: на файлы
  проекта через `../` до корня проекта.
- После переноса или переименования файлов — проверить скриптом, что
  все относительные ссылки ведут на существующие файлы и заголовки,
  и исправить битые. Ссылки на заметки бывают и вне `notes/`, например
  в README проекта.
