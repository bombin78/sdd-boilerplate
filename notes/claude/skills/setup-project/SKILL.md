Аргумент: $ARGUMENTS

Скилл из двух частей: «Стек» и «Читатель». Без аргумента выполняются
обе, по порядку: темы для читателя зависят от стека. С аргументом
«стек» или «читатель» — только эта часть.

Вопросы задавай инструментом AskUserQuestion: до 4 вопросов за раз,
у вопроса от 2 до 4 вариантов, свой ответ пользователь пишет в «Other».
Ни одного файла не меняй до шага «Итог и запись».

## Часть 1. Стек

### 1.1. Определить стек по файлам

Прочитай, что есть в корне проекта:

- файлы зависимостей: `package.json`, `pyproject.toml`,
  `requirements.txt`, `go.mod`, `Cargo.toml`, `composer.json`, `Gemfile`;
- файлы настроек: `tsconfig.json`, `next.config.*`, `vite.config.*`,
  `nuxt.config.*`, `tailwind.config.*`, `postcss.config.*`,
  `components.json` (shadcn/ui), `prisma/schema.prisma`, `drizzle.config.*`,
  `docker-compose.yml`, `Dockerfile`, `.github/workflows/`;
- папки верхнего уровня, кроме `notes/`, `.claude/`, `.git/`,
  `node_modules/` и папок сборки.

Из них составь:

- технологии и версии. Версию бери из файла зависимостей или
  из установленного пакета, а не по памяти;
- команды проверки: lint, проверка типов, тесты, сборка. В
  `package.json` — раздел `scripts`;
- папки с кодом для шаблонов путей;
- документацию в проекте: папки `docs/` внутри установленных пакетов,
  например `node_modules/next/dist/docs/`.

Покажи пользователю найденное одним списком и спроси, всё ли верно.
Исправления пользователя важнее того, что найдено в файлах.

Если `stack-rules.md` уже заполнен, сравни найденное с записанным
и спрашивай только о различиях: новая библиотека, другая версия,
пропавшая команда. Раздел «Код» при повторном запуске не меняй.

### 1.2. Пустой проект: спросить о технологиях

Если файлов зависимостей нет, проект пустой. Тогда спроси по очереди,
каждый раз с вариантами и с «Other»:

1. Что это за проект: сайт с интерфейсом, API без интерфейса,
   программа для командной строки, библиотека.
2. Язык: TypeScript, JavaScript, Python, Go или другой.
3. Фреймворк. Варианты подбери под ответы 1 и 2: например, для сайта
   на TypeScript — Next.js, Nuxt, SvelteKit, Vite с React.
4. Стили и компоненты, если есть интерфейс: Tailwind, CSS-модули,
   shadcn/ui, другая библиотека компонентов или без неё.
5. Данные: база данных и как с ней работать — PostgreSQL, SQLite,
   MongoDB, без базы; Prisma, Drizzle, SQL без ORM.
6. Вход пользователей: Auth.js, своя реализация, сервис, без входа.
7. Тесты: Vitest, Jest, Playwright, pytest, пока без тестов.
8. Запуск и выкладка: Docker, сервер, хостинг, пока не решено.
9. Менеджер пакетов, если язык его предполагает: npm, pnpm, yarn, bun.

Ответ «пока не решено» — нормальный ответ. В `stack-rules.md` такой
пункт записывается как «не выбрано», и при следующем запуске
`/setup-project стек` вопрос задаётся снова.

Команды проверки для пустого проекта предложи по выбранному стеку
и отметь в `stack-rules.md`: «предложено, проверить после установки».
Шаблоны путей предложи по тем папкам, которые создаёт генератор
выбранного фреймворка.

### 1.3. Вопросы, которых нет в файлах

Даже если стек найден по файлам, спроси:

- если есть интерфейс — на каких ширинах экрана проверять вёрстку,
  в каких темах (светлая, тёмная);
- какие части кода не трогать без задачи: например, схему базы
  и серверную логику;
- для известного стека: добавить ли готовый набор правил в раздел
  «Код» и «Вёрстка». Готовые наборы — в комментариях `stack-rules.md`.

## Часть 2. Читатель

Читатель — тот, кому Claude пишет ответы. Раздел «Читатель»
в `notes/claude/answer-rules.md` создаётся при каждом запуске заново:
старые списки не берутся за основу.

### 2.1. Составить темы

Темы — из двух источников:

- технологии из части 1. Крупную технологию дели на 2–4 темы по тому,
  что в ней встречается в работе. Например, Next.js: App Router
  (`page`, `layout`, адреса страниц); серверные компоненты
  и `"use client"`; Server Actions; кэширование.
- общие темы, которые встречаются в любом веб-проекте: HTTP
  (заголовки, коды статуса), cookies, рендеринг на сервере
  и в браузере, сессии и JWT, хеширование паролей, git, Docker,
  терминал Linux.

Если части 1 не было, прочитай технологии из раздела «Стек»
`stack-rules.md`. Если он не заполнен, сначала выполни часть 1.

### 2.2. Спросить

1. «Что из этого вы знаете уверенно?» — AskUserQuestion
   с `multiSelect: true`. До 4 вопросов за раз, по 4 темы в каждом,
   вопрос назван по группе тем.
2. «Что из оставшегося знаете частично: общее понятие есть, детали
   объяснять?» — так же, только по темам, которые не выбраны в шаге 1.
3. Всё, что не выбрано ни в шаге 1, ни в шаге 2, попадает в «Не знаю».
4. Один вопрос со свободным ответом: что уточнить по выбранным темам.
   Например, «TypeScript: пишу свои типы, дженерики знаю частично».

## Итог и запись

1. Покажи в чате, что запишешь:
   - `notes/claude/stack-rules.md` — разделы «Стек», «Документация»,
     «Проверка», «Вёрстка», а в разделе «Код» — только то, что
     пользователь выбрал в шаге 1.3;
   - шаблоны путей — одинаковые в начале `stack-rules.md`
     и `notes/claude/code-rules.md`;
   - раздел «Читатель» в `notes/claude/answer-rules.md` — три списка.
2. Запиши только после явного согласия пользователя.
3. В `stack-rules.md` замени строки «(заполняет /setup-project)».
   Комментарии `<!-- -->` с примерами оставь: они помогают при
   следующем запуске.
4. В `answer-rules.md` замени только три списка раздела «Читатель».
   Комментарий-болванку над ними удали. Остальные разделы файла
   не трогай.
5. Скажи пользователю, что `answer-rules.md` загружается при старте
   сессии: новые списки подействуют после перезапуска Claude Code.
