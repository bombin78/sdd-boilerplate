# Правила кода

Как Claude пишет, меняет и проверяет код проекта. Файл загружается,
когда Claude читает или правит файл кода: через ссылку
`.claude/rules/code-rules.md` в проекте, шаблоны путей — в начале файла.

Здесь только правила, которые не зависят от стека. Правила стека,
команды проверки и где лежит документация — в
`notes/claude/stack-rules.md`. Формат коммитов, записи в git и долгие
проверки — в `notes/claude/common-rules.md`,
порядок приёмки этапа — в `notes/tasks/README.md`.

## Перед кодом

- Прочитать код, который меняется, и код рядом с ним. Писать так же:
  те же имена, те же приёмы, столько же комментариев.
- То, что зависит от версии библиотеки, сверять с документацией
  установленной версии.

## Объём правки

- Менять только то, что нужно для задачи. Заметил другое — записать
  новым пунктом в `notes/backlog.md`, по формату из начала этого
  файла, а не править заодно. В файл этапа отложенное
  не пишется.
- Код, который задача не трогает, не менять, даже если его можно
  улучшить. Какие части кода особенно не трогать без задачи — в
  `stack-rules.md`, раздел «Код».
- Новые библиотеки — только с согласия пользователя.

## Типы

- Тип описывает то, что бывает на самом деле. Если значения может
  не быть, это видно в самом типе, а не в одном месте использования.
- Без типа «что угодно», если язык его позволяет: `any` в TypeScript
  и подобные.

## Тесты

- Пункт «Готово, когда», который можно проверить автотестом,
  проверяется автотестом. Тест пишется в том же этапе, что и код,
  и остаётся в проекте: так другая задача не сломает этот пункт
  незаметно.
- Тест пишется тем фреймворком и в той папке, которые уже есть
  в проекте: раздел «Тесты и CI» `notes/project.md`. Если тестов
  в проекте нет, фреймворк тестов ставится только с согласия
  пользователя, как любая новая библиотека. Без согласия пункт
  проверяется командой, в браузере или сверкой с источником.
- В отчёте у такого пункта — файл и имя теста.

## Комментарии

Язык и подробность — как в файле, который меняется. Если в проекте
выбрано общее правило, оно записано в `stack-rules.md`, раздел «Код».

## После правок

1. После каждой правки — команды списка «После каждой правки» раздела
   «Проверка» `stack-rules.md`.
2. Перед отчётом — команды списка «Перед отчётом» того же раздела,
   все без ошибок.
3. Если менялся интерфейс — проверить в браузере так, как сказано
   в разделе «Вёрстка» `stack-rules.md` и в описании задачи.
4. Отчитаться: какие файлы и что изменилось, что проверено и как,
   номера новых пунктов в `notes/backlog.md`. Если работа по этапу задачи,
   последняя строка отчёта — статус в начале файла этапа: «Статус
   в файле этапа: ждёт приёмки».
