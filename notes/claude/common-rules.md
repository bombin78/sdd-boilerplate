# Общие правила

Правила для любой работы в проекте: с кодом, заметками, сервером.
Файл подключается в каждую сессию через `CLAUDE.local.md` в корне
проекта.

Где лежат остальные правила:

| Файл | О чём | Когда загружается |
|---|---|---|
| `notes/claude/answer-rules.md` | ответы и тексты для пользователя | всегда |
| `notes/claude/code-rules.md` | код проекта: общие правила | при работе с файлами кода, через `.claude/rules/` |
| `notes/claude/stack-rules.md` | код проекта: правила стека, команды проверки, документация | при работе с файлами кода, через `.claude/rules/` |
| `notes/CLAUDE.md` | папка `notes/` | при работе с файлами в `notes/` |
| `AGENTS.md` проекта | правила проекта для ИИ-агентов; генератор стека может дописать туда своё. Где формат коммитов — в разделе «Git» ниже | всегда |
| `notes/project.md` | описание проекта: продукт, карта кода, сценарии, данные | читать перед планом этапа и в `/explain` |
| `notes/tasks/README.md` | задачи, этапы, приёмка | читать при работе с задачей |
| `notes/tasks/instruction-mode.md` | этап-инструкция, который выполняет пользователь | читать, если этап — инструкция по шагам |

## Владелец заметок и трекер

Владелец заметок: (заполняет /setup-project)

Трекер задач: (заполняет /setup-project)

У репозитория `notes/` в каждый момент один владелец. Если заметки
передают другому программисту, новый владелец заменяет строку
«Владелец заметок» своим именем через `/setup-project читатель`.
Трекер задач — название трекера, например Jira, или «нет». Что из
этого попадает в имя ветки — в `notes/tasks/README.md`, раздел «Имена
веток».

## Git

- Записи в git делает пользователь: `add`, `commit`, `push`, `pull`,
  `reset`, `restore`, создание и удаление веток. Это касается и проекта,
  и репозитория `notes/`, в том числе через `git -C`. Хук
  `notes/hooks/block-git-writes.py` блокирует такие команды. Если он
  сработал, правило работает — обходить его не нужно.
- Чтение разрешено: `status`, `log`, `diff`, `show`, `ls-remote`,
  `fetch` для просмотра.
- После правок — назвать изменённые файлы и предложить команду
  коммита. Формат сообщения — в `AGENTS.md` проекта.
- Во время работы над этапом коммит в `notes/` предлагается только
  после приёмки этапа: один коммит на этап. Статус «ждёт приёмки»
  лежит без коммита до приёмки.
- «Закрывай этап» значит обновить файлы, а не закоммитить их.

## Работа над задачей

Если ветка вида `<направление>/<метка>/T<задача>-S<этап>` или
`<направление>/<метка>/T<задача>`, это работа над задачей: перед первым
действием прочитать `notes/tasks/README.md`. В нём порядок работы,
когда менять статус и что такое метка. Файл этапа находится
по направлению и последней части имени ветки, метка не важна:
`app/PROJ-123/T0001-S0001` — `notes/tasks/app/0001-task/0001-stage.md`,
`infra/ivan-petrov/T0001` — `notes/tasks/infra/0001-task.md`.

Ветки ещё нет, когда задачу только создают. Поэтому просьба создать
задачу или этап, расписать инструкцию по шагам или принять этап — тоже
работа над задачей: перед первым действием прочитать
`notes/tasks/README.md`, на какой бы ветке ни шла работа.

## Долгие проверки

Быстрые проверки без следов — команды проверки из раздела «Проверка»
`notes/claude/stack-rules.md`, поиск, короткий скрипт — можно
запускать сразу.

Долгое или оставляющее следы — сборка образа, запуск контейнеров, запись
в базу, тестовые пользователи — только после согласия пользователя.
Сначала рассказать, что найдено при чтении, и спросить, проверять ли
запуском. Если в описании задачи дано разрешение на что-то из этого,
оно действует только в этой задаче.

## Поиск

`grep -r` в этой среде пропускает всё, что git игнорирует по
`.gitignore` и `.git/info/exclude`: `notes/`, `.env`, `CLAUDE.local.md`.
Для поиска по проекту вместе с заметками — `command grep -r` или явный путь (`notes`,
`.claude`). Строки в заметках переносятся, поэтому искать по короткому
куску фразы.
