# SDD-бойлерплейт для проектов с Claude Code

У заготовки две цели.

Первая — вести проект по SDD: сначала задача и её условия приёмки
пишутся в файл, потом по ним пишется код. При этом задача
разбивается на этапы, и у каждого этапа свои условия приёмки.
Маленькая задача сама и есть один этап. Для каждого этапа
выбирается, как он делается. Либо код пишет Claude Code. Либо Claude
пишет инструкцию по шагам с кодом и командами, а пользователь
переносит код в файлы, меняет его, где считает нужным, и выполняет
команды. Пользователь принимает каждый этап по условиям приёмки.

Вторая — хранить служебные материалы разработчика в закрытом
репозитории `notes/`, отдельно от репозитория проекта. Файлы задач
из первой цели лежат именно там. Там же лежат правила, по которым
Claude пишет код и отвечает, отложенные замечания, сохранённые ответы
Claude на вопросы по коду, разборы тем, идеи и справочники. Репозиторий
`notes/` находится внутри папки проекта, но в репозиторий проекта
не попадает. У репозитория `notes/` один владелец. Другие программисты
на проекте его не видят и могут вести свой. Но если владелец передаёт
незаконченные задачи другому программисту, предполагается, что он
передаёт ему репозиторий `notes/` целиком.

Здесь нет кода приложения. Есть только то, что не меняется от проекта
к проекту: правила для Claude, скиллы, агент, хуки, настройки Claude Code
и болванки задач с комментариями.

Этот `README.md` в новый проект не копируется.

## Что даёт заготовка

### Работает сразу после подключения к проекту

- хуки, которые не дают Claude выполнять `git add`, `commit`, `push`
  и другие команды, меняющие git, и удалять файлы в `notes/`;
- настройки Claude Code в `.claude/settings.json`. Песочница не даёт
  командам Claude читать домашнюю папку, кроме самого проекта.
  Отдельные правила запрещают Claude читать `~/.ssh`,
  `~/.git-credentials`, историю команд и другие файлы с ключами
  и токенами;
- скилл `/explain` и агент `answer-reviewer`. Claude объясняет код
  проекта, а агент перед показом пользователю проверяет объяснение
  по правилам из `notes/claude/answer-rules.md`.

### Используется, когда вы работаете над задачами

- файлы задач или папки задач с общим описанием и файлами этапов.
  Условия приёмки содержатся в файле задачи и в файлах этапов;
- порядок приёмки по этапам.

## Что внутри

```
├── AGENTS.md                ← формат коммитов; генератор стека может дописать своё
├── CLAUDE.md                ← подключает AGENTS.md
├── CLAUDE.local.md          ← подключает правила из notes/claude/
├── .githooks/pre-commit     ← запрещает коммиты в main
├── .claude/
│   ├── settings.json        ← права и песочница Claude Code
│   ├── settings.local.json  ← хуки из notes/hooks/, переменная для npm
│   ├── rules/               ← ссылки на code-rules.md и stack-rules.md
│   ├── skills/              ← ссылки на скиллы /explain и /setup-project
│   └── agents/              ← ссылка на агента answer-reviewer
└── notes/                   ← закрытый служебный репозиторий разработчика
    ├── README.md            ← как заметки подключены к проекту
    ├── CLAUDE.md            ← правила работы с notes/
    ├── backlog.md           ← отложенные замечания, болванка пункта
    ├── claude/              ← правила, скиллы, агент
    ├── hooks/               ← хуки: защита заметок, запрет записи в git
    ├── docs/, ideas/        ← разборы тем и идеи, пока пустые
    └── tasks/               ← задачи: правила, списки, болванки
```

Подробно о каждом файле в `.claude/` и о том, когда Claude Code его
загружает, — в `notes/README.md`.

## Что нужно на компьютере

**Claude Code.** С бойлерплейтом работают в Claude Code одним из двух
способов:

- в VS Code или редакторе на его основе (Cursor и другие) — через
  расширение Claude Code. В редакторе откройте панель расширений
  (Ctrl+Shift+X, на macOS Cmd+Shift+X), найдите «Claude Code»
  и нажмите Install. Нужен VS Code 1.94.0 или новее. Подробно —
  https://code.claude.com/docs/en/vs-code. Консольная версия расширению
  не нужна: в нём есть своя копия Claude Code для панели чата.
  Консольная версия понадобится, только если вы захотите запускать
  `claude` во встроенном терминале редактора;
- в консоли — через консольную версию Claude Code. В Linux и macOS она
  ставится командой ниже, подробно — https://code.claude.com/docs/en/setup.
  После установки откройте новое окно терминала.

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

**Остальные программы.** Как проверить и установить `git`, `python3`
и `jq` — в `notes/README.md`, раздел «Как собрать всё заново», пункт 1.
Для шага 2 нужен ещё `rsync`. Проверьте его:

```bash
rsync --version
```

Команда выводит номер версии. Если вместо версии пришло
`command not found`, установите `rsync`: в Ubuntu и Debian —
`sudo apt install rsync`, в других системах — их менеджером пакетов.

## Как начать новый проект

**1. Создать проект.** Если у стека есть генератор проекта (например,
`create-next-app` для Next.js), запустить его первым: он создаёт папки кода, `package.json` и иногда свои `AGENTS.md`
и `CLAUDE.md`.

```bash
npx create-next-app@latest my-app   # пример для Next.js
cd my-app
```

Если генератора нет, создать пустую папку и `git init` в ней.

**2. Скопировать бойлерплейт.** Если бойлерплейта ещё нет
на компьютере, склонируйте его:

```bash
git clone https://github.com/bombin78/sdd-boilerplate.git ~/dev/sdd-boilerplate
```

Затем из папки нового проекта:

```bash
rsync -a --ignore-existing --exclude /.git --exclude /README.md ~/dev/sdd-boilerplate/ ./
```

- `-a` — копирует вместе с символическими ссылками и правами файлов;
- `--ignore-existing` — не трогает файлы, которые уже создал генератор;
- `--exclude /.git`, `--exclude /README.md` — не копирует git
  бойлерплейта и этот файл. Слеш в начале значит «только в корне»:
  `notes/README.md` копируется.

Если генератор уже создал `AGENTS.md`, допишите в его конец раздел
«Commit messages» из `AGENTS.md` бойлерплейта.

**3. Скрыть от git проекта заметки и личную настройку Claude.** Строки
для `.git/info/exclude`, команда, которая их добавляет, и проверка —
в `notes/README.md`, раздел «Строки в `.git/info/exclude` проекта».
В `.gitignore` проекта эти строки не пишут: `.gitignore` попадает
в коммит, а для других программистов проекта эти строки — лишняя
информация.

**4. Решить, нужен ли хук `pre-commit`.** Хук
`.githooks/pre-commit` отменяет коммит, если текущая ветка — `main`.
Тогда изменения попадают в `main` только через pull request.

Если хук нужен, включить его:

```bash
git config core.hooksPath .githooks
```

Эта настройка записывается в `.git/config` и действует только в этом
клоне. В каждом новом клоне проекта команду нужно выполнить снова.
Другие программисты получают хук вместе с репозиторием проекта,
а этот README у них не появится. Поэтому допишите команду в README
проекта.

Если хук не нужен, удалить его папку:

```bash
rm -r .githooks
```

**5. Сделать `notes/` отдельным репозиторием:**

```bash
cd notes
git init
git remote add origin <адрес закрытого репозитория notes/>
cd ..
```

Первый коммит в `notes/` делается после шага 7, когда правила заполнены.

**6. Заменить строки в угловых скобках** в `notes/README.md`: имя
проекта и адреса репозиториев.

**7. Настроить под проект и под себя.** Открыть сессию Claude Code
в корне проекта: в консоли — командой `claude`, в редакторе — открыть
папку проекта и панель Claude Code. В сессии запустить `/setup-project`.
Скилл:

- определяет стек по файлам проекта, а в пустом проекте задаёт
  вопросы о технологиях;
- заполняет `notes/claude/stack-rules.md` и шаблоны путей в
  `notes/claude/code-rules.md`;
- спрашивает, ведутся ли задачи в трекере, и ваше имя для веток,
  и записывает ответы в `notes/claude/common-rules.md`;
- спрашивает, какие темы вы знаете, и заново создаёт раздел «Читатель»
  в `notes/claude/answer-rules.md`.

После этого перезапустить сессию: правила ответов загружаются при
старте.

**8. Проверить, что всё подключено.** Список проверок — в
`notes/README.md`, раздел «Как собрать всё заново», пункты 7–9.

**9. Заменить болванки своими задачами.** Примеры лежат в
`notes/tasks/registry/`, `notes/tasks/app/`, `notes/tasks/infra/`
и в `notes/backlog.md`. Как устроены задачи — в `notes/tasks/README.md`.

## Для тех, кто меняет сам бойлерплейт

Файл `.claude/settings.local.json` лежит в репозитории
`sdd-boilerplate` на GitHub. Но когда вы работаете с клоном бойлерплейта
в Claude Code, Claude Code сам добавляет строку
`**/.claude/settings.local.json` в глобальный список игнорирования git,
обычно `~/.config/git/ignore`, если её там ещё нет, и возвращает её,
если её удалить. Эта строка не мешает: git игнорирует только файлы, которых ещё нет ни
в одном коммите. Если файл уже закоммичен, git показывает его изменения
в `git status`, даже когда под него подходит правило игнорирования.
Поэтому строку в глобальном списке трогать не нужно.

Если файл когда-нибудь удалят из коммитов `sdd-boilerplate`, обычный
`git add` его снова не добавит: помешает эта строка. Тогда его
добавляют в обход правила: `git add -f .claude/settings.local.json`.

Claude Code записывает в этот файл и разрешения: например, когда вы
разрешаете команду и просите больше не спрашивать. В `sdd-boilerplate`
такие записи появляются в `git status` как изменения файла. Не
коммитьте их: в образце должны остаться только ключи `env` и `hooks`,
как в `notes/README.md`, раздел «`.claude/settings.local.json`».
Отменить такие изменения можно командой
`git restore .claude/settings.local.json`.
